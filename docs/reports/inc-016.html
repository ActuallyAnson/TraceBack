Causal chain

  1. Confirmed: orders reduced its timeout for inventory calls from 800 ms to 9 ms via a config change.
    • ops-E0001 +49.705s ops config_change orders {"key":"timeout.inventory_ms","new":9,"old":800}
    • orders-L00034 +49.705s log orders info event=config_changed "config reloaded timeout.inventory_ms" {"key":"timeout.inventory_ms","new":9,"old":800}
  2. Confirmed: with the 9 ms timeout, orders started timing out calls to inventory (the calls ended after ≈9 ms with a timeout error).
    • orders-S00b1f +49.789s span orders client reserve -> inventory status=0 dur=9ms attempt=1 error=timeout trace=080de32d
    • orders-S00b23 +49.871s span orders client reserve -> inventory status=0 dur=9ms attempt=1 error=timeout trace=bcbeeeea
    • orders-S00b24 +49.893s span orders client reserve -> inventory status=0 dur=9ms attempt=1 error=timeout trace=50978c63
  3. Confirmed: orders retried the failed inventory calls with a short backoff of about 50 ms.
    • orders-L00037 +49.881s log orders warn event=retry_scheduled "retrying call attempt=2" trace=bcbeeeea {"backoff_ms":50,"next_attempt":2,"peer":"inventory"}
    • orders-L00039 +49.903s log orders warn event=retry_scheduled "retrying call attempt=2" trace=50978c63 {"backoff_ms":50,"next_attempt":2,"peer":"inventory"}
    • orders-L0003b +49.913s log orders warn event=retry_scheduled "retrying call attempt=2" trace=0e6eaa70 {"backoff_ms":50,"next_attempt":2,"peer":"inventory"}
  4. Uncertain: the retry load caused orders to process more work, slowing its own response times (order server spans grew to ~110‑170 ms).
    • orders-S004c9 +19.498s span orders server create_order status=200 dur=114ms trace=82ec5b19
    • orders-S009a9 +41.076s span orders server create_order status=200 dur=171ms trace=ab0530f6
    • orders-S009ea +42.504s span orders server create_order status=200 dur=116ms trace=28ef2ca9
  5. Confirmed: gateway timed out waiting for orders, producing 504 upstream_timeout errors seen by users.
    • gateway-S00772 +49.866s span gateway server POST /checkout status=504 dur=76ms error=upstream_timeout trace=bcbeeeea

Alternatives considered

  • dependency_slow in orders: covers zero failed traces and its slowdown alone cannot explain the inventory timeouts and retries.
  • edge_unreachable in inventory: its onset (+51.113 s) is after the symptom start and likely resulted from overload due to retries, not an initial network failure.
