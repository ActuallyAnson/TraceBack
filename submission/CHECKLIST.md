## Quality bar from the brief (all verifiable)

| Item | Status | Check |
|---|---|---|
| One command builds everything | ✅ | `make build` |
| One command runs the demo end to end | ✅ | `make demo` (offline, no key) |
| Results table (3 systems × metrics) generated by a script | ✅ | `make results`; `make results-check` fails if the README drifts |
| Unit tests: correlator, clock-skew handling, citation validation | ✅ | `make test` |
| No hardcoded answers / no leaked labels | ✅ | analyzer and prompts never read labels; `tests/test_sim.cpp` checks observable files carry no label strings |
| Test set locked before tuning; never edited after results | ✅ | `eval/LOCK_HISTORY.md`, `eval/test_runs.log` |
| No secrets in the repo | ✅ | key is only read from `NEBIUS_API_KEY`; see "Before you submit" |
| License file and architecture diagram in the README | ✅ | `LICENSE`, mermaid diagram |
| Honest limitations in the README | ✅ | README sections on results, generalization check and limitations |
| Generalization check on a second topology, no tuning | ✅ | `eval/topology2/PLAN.md` (pre-registered), `make topology2`, README section |

## Before you submit (about 30 minutes)

1. Open the demo URL in a private window; click through one incident (Play walkthrough).
2. Look at the repo page: license shows in About; README renders the diagram and the results table.
3. `git clone` into a fresh directory and run `make build test demo` once more.
4. Record the video from `submission/VIDEO_OUTLINE.md`; upload to YouTube as **Public**; confirm it is under 3:00.
5. Fill the Devpost form: track = Best Apps and Agents; paste the description and feedback; add repo URL, demo URL, video URL.
6. After submitting: revoke or rotate your Nebius API key if you no longer need it, and remove it from `~/.zshrc`.
7. Do not push commits that change results or prompts after submitting unless you resubmit; judging uses what the repo shows.
